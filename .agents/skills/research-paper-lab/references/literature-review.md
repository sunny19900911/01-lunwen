# 文献复查：让原文与当前研究逐项对照

将用户以往收集的论文作为原文库，核对当前猜想、推导、证明与反例是否已有先例、是否满足同样假设、是否真正冲突。文献复查者独立提交比较证据，不能代替验证者审核证明，也不能替主控裁决主张。

本流程不假定当前已有 PDF。先盘点获准材料及其可访问程度；没有全文时记录缺口并完成能做的书目和命题对照，不虚构原文内容。不访问未经授权的账户，不绕过访问限制或批量抓取版权全文；角色使用当前任务的子代理，不自行创建用户聊天。

## 何时触发

- 启动课题或恢复研究时，盘点原文库，优先复查与中心主张直接相关的材料。
- 新增或修订猜想、假设、关键推导、证明、反例时，核查已有结论与当前命题的关系。
- 新原文、勘误或不同版本进入资料库时，定位受影响的主张、图表、选题卡与稿件。
- 出现“首次”“普遍成立”“已有文献证明”等强表述，或准备定稿贡献、引言和结论时。
- 文献结果与本地推导或实验不一致时，启动有范围的冲突复查。

每轮优先处理最影响结论或选题的一至三项对照，不重复通读整个库。以原文版本＋命题版本＋比较问题形成去重键；没有新输入时复用已审核记录。十分钟检查点按[协作协议](collaboration-protocol.md)返回增量或缺口。

## 目录、输入输出与所有权

下列路径均相对于实际课题 `papers/<topic>/`，不为占位创建空目录。

| 位置 | 内容 | 所有者 |
|---|---|---|
| `literature/` | 获准使用的全文、附件及其来源清单；可沿用既有子目录 | 原始文件只读，新增原文按授权导入 |
| `literature/index.md` | L-ID、书目信息、版本、可访问程度、原文定位、主题与比较记录索引 | 文献复查者单写；已有其他格式时沿用 |
| `research/roles/literature/` | 对照表、摘录定位、冲突拆解、反馈与待取材料清单 | 文献复查者单写 |
| `research/claims.md` | 主张、证据关系、状态与后续任务 | 仍由主控单写 |
| 稿件、验证记录、选题卡 | 各角色接收文献反馈后的修订 | 原指定所有者；复查者只交建议 |

输入至少包含：冻结的 C-ID 与版本、精确命题及假设、待比证明或反例、指定原文或资料库路径、本轮问题和预算。存在选题卡或已写段落时一并提供，避免只检索相似关键词。

每个原文的索引最少记录：L-ID、题名、作者、年份、来源、DOI/稳定链接（能核验时）、本地路径、版本或文件指纹、全文/部分全文/仅摘要/仅书目状态。预印本、正式版、勘误和撤回记录注明关系，不能静默替换为同一文本。

索引记录不代表全文已获取或他人可访问。本地原文路径若不能共享，应写明可用的获取条件；全文与大附件是否进入 Git 沿用课题授权和仓库约定。

## 从原文建立可定位的证据

1. 核对书目与实际文件是否一致，确认正在读的版本；先定位定理、定义、方法、结果及其上下文。
2. 为相关主张记录章节、定理/命题编号、印刷页码和 PDF 页序（存在时），并记录式号、图号或表号。HTML 无页码时记录稳定链接、节标题及可识别段落。
3. 分别提取“原文说什么”“原文用了哪些前提”“我们怎样解释其关系”。短摘录与转述分开；不把长篇原文复制进研究日志。
4. OCR 文本、二次转述或截图中的关键符号需回看原页。无法确认负号、上下标、量词或图轴时标记未核验，不以提取文本直接裁决。
5. 原文只给经验结果就登记为经验结果；使用定理名称或引用另一论文，不代表已经核查完整证明。未读到的证明依赖列入缺口。

全文不可得时，可以报告摘要声称的主题和候选相关性；不能依据摘要判定证明有效、反例失效或研究具有创新性。只核实书目也不能写成“原文已支持本句”。

## 同一命题与同一假设的比较

对每组“C-ID＋L-ID”逐项填写，不能仅凭题目相似认定重复或冲突。

| 维度 | 必须核对 |
|---|---|
| 对象与模型 | 线性/非线性、离散/连续、自由度、边界条件、阻尼/本构与近似 |
| 变量与指标 | 符号映射、单位、坐标、绝对/相对量、峰值/均值、归一化与统计口径 |
| 命题强度 | 必要/充分、局部/全局、逐例/平均、存在/任意、确定性/概率陈述 |
| 前提与范围 | 参数域、输入集合、初始条件、正则性、极限过程及排除情况 |
| 证据与方法 | 完整证明、条件性推导、数值模拟、物理试验或拟合；误差与验证条件 |
| 结果与例外 | 相同指标下的结论方向、条件是否遗漏、反例是否满足双方全部前提 |

给出关系判断：`same-claim`（同一命题）、`conditional-extension`（条件改变后的扩展）、`related-not-equivalent`（相关但不等价）、`apparent-conflict`（待拆解冲突）、`insufficient-text`（原文不足）。同时记录依据和置信限制；关系标签不直接变更主张真假。

已有文献覆盖当前结果时，明确指出重复范围，候选贡献可转向边界、不同假设、独立验证或可复现实现。未发现相同结论只能写“在已检查资料中未发现”；记录实际覆盖的文献范围与未查部分，不能据此宣称首次。

## 冲突怎样拆解

1. 固定双方原命题、版本与原文定位，保留冲突记录，不先选支持本研究的一方。
2. 先排除符号、单位、指标、输入、参数域、数据配对和近似不同造成的表面矛盾。
3. 若前提不同，写明映射与差异，分别保留结论；不得拼接成双方都未证明的更强命题。
4. 若同命题同前提仍不一致，把争议缩为一个可核验步骤或最小算例，交验证者独立复算；需要实验时由主控分配预算。
5. 本地反例必须满足原文全部前提，并核对实现与数值精度；原文发表或被多次引用也不替代该检查。尚未复核时只称候选反例或待解冲突。
6. 将“已解释差异、仍有逻辑缺口、需要全文/附件、需要独立实验”分开返回。主控更新账本；原证明、反例和负结果保留历史版本。

## 统一输出与反馈对象

每次复查输出一个可追溯比较包，字段可按任务缩减：

```text
轮次 / 日期 / 复查者 / 本轮预算：
C-ID与版本 / 具体比较问题：
L-ID / 原文版本 / 全文可得程度 / 原文指纹：
页码、章节、定理、公式、图表定位：
原文主张 / 原文前提 / 证据类型：
符号与指标映射 / 相同条件 / 不同条件：
关系判断 / 依据 / 未核验依赖：
支持什么 / 反对什么 / 不能支持什么：
冲突拆解 / 需要验证的最小步骤或实验：
影响的主张、稿件位置、选题卡字段：
输出路径 / 下一步 / 缺少的具体材料：
```

| 接收者 | 反馈重点 |
|---|---|
| 主控 | 新增文献证据、潜在重复、关键冲突、受影响 C-ID 和下一项最高价值检验；仅提出账本修订建议 |
| 验证者 | 原命题与前提的精确定位、符号映射、证明依赖、反例有效性待查点；不以文献权威替代其独立审核 |
| 论文作者 | 哪个具体句子可引用哪个位置、所需限定、哪些贡献应收窄；按[论文蓝图](paper-blueprint.md)映射章节 |
| 选题卡负责人 | 已有工作覆盖范围、真实差异、未解决边界、材料缺口及创新性核查状态；建议保留、收窄、合并或暂缓 |

尚未读取原文时，作者收到的是“待核查引用”，选题卡收到的是“候选差异”，不能当作已经建立的贡献。主控决定优先级与状态，卡片所有者负责修订卡片。

## 独立子代理提示词

> 你是文献复查者。读取[冻结的C-ID与版本、命题和假设]、[当前证明/反例]及[获准原文库与索引]，在[预算]内只处理[具体比较问题]。先核实原文版本与可得程度，再逐项比较对象、变量、指标、量词、前提、参数域与证据类型。对关键结论给出可复查的页、式、定理或图表位置；区分原文陈述、你的转述及尚未核验的解释。发现冲突先排除口径不同，再提出最小独立检验。不依据摘要裁决证明或创新性，不把“未查到”写成“首次”。仅写[课题]/research/roles/literature/与[课题]/literature/index.md；原文只读，不改claims、稿件或选题卡。返回比较包，以及分别给主控、验证者、作者、选题卡负责人的修订建议。没有全文就报告准确缺口并完成可做部分；不访问账户、不抓取受限全文、不创建用户聊天。

角色只接收当前比较所需的上下文，避免先被“团队已同意”的结论锚定。并发资源不足时优先复查决定中心主张或选题去留的材料，不要求所有角色同时在线。

验收标准是结论能定位到原文、关系判断能由另一人复核、缺口和不同条件没有被掩盖；不是新增多少条引用。返回[技能入口](../SKILL.md)继续研究闭环。

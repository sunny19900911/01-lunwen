# 多角色论文研究室

把一个研究问题推进为可复核的论证和论文。主控组织五种研究职责：猜想、验证、文献复查、实验拟合、写作，并维护选题卡和演变历史供用户最终决策。角色可以自主推导、互相质疑和提出下一步，但任何结论的强度必须与实际证据匹配。

## 选择工作方式

- **设计框架或创建 skill**：交付协作设计、论文蓝图和角色提示词。讨论中的“每十分钟”“几个对话框”不自动意味着现在创建后台任务或新聊天。
- **启动或继续研究**：读现有材料、约定和证据状态，完成一个有范围的研究循环；有可并行的工作时使用子代理。参见 [协作协议](references/collaboration-protocol.md)。
- **用户明确要求定时继续**：先使一轮手动研究可运行并落盘，再使用当前环境的正式自动化工具设置同一聊天的定时唤醒。未获工具成功结果不能宣称已安排；没有调度能力时明确报告，只交付可继续执行的方案。

遵循课题已有格式、语言、目录和命名。本机默认中文；跨项目使用时尊重用户语言。不要将本次课题参数写回通用 skill。

## 建立研究契约

先读适用的 AGENTS.md、相关稿件、模型/数据说明和脚本。范围不明时先做资料地图，不擅自选一个现有论文项目改写。

复用现有研究目录；没有约定时在课题下建立 `research/`。将 [研究计划模板](assets/research-plan.template.md) 的必要字段写入 `research/plan.md`，无需为了模板创建空文件。至少明确：

- 核心问题、研究对象、候选贡献和成功/失败判据。
- 原始资料与已收集论文路径、已有稿件、数据权限、可用脚本与计算条件。
- 当前运行边界：本轮结束条件、实验规模/超时、检查点间隔和后续是否已调度。
- 分工、文件所有者、未提交修改、允许的外部操作；选题卡复核/快照间隔和用户已批准的研究主线。

缺少课题或数据时交付通用蓝图和数据需求，不虚构实验结果。用户未给持续运行预算时，默认先完成一轮可检查的研究，将后续建议写清；不要启动无期限后台运行。用户已给明确范围与预算时继续在该边界内推进。

## 分配角色与可写范围

| 角色 | 研究职责 | 默认输出所有权 |
|---|---|---|
| 主控 | 问题分解、实验优先级、证据裁决、检查点、选题卡与下一轮任务 | `research/plan.md`、`claims.md`、`rounds/`、`runs.md`、`topic-cards/` |
| 猜想者 | 根据异常/文献提出可证伪命题，声明量词和适用条件 | `research/roles/ideation/` |
| 验证者 | 独立审查推导、构造反例、检查假设与数值误差 | `research/roles/verification/` |
| 文献复查者 | 读取已收集论文，将当前猜想、证明与反例和原文逐条比较 | `research/roles/literature/`、课题 `literature/index.md` |
| 实验拟合者 | 数据口径、模型拟合、外部验证、误差与适用域 | `research/roles/experiments/`、获分配的 `experiments/` |
| 论文作者 | 按证据组织章节、图表、摘要与结论，暴露缺口 | `research/roles/writing/`、获分配的 `manuscript/` |

具体角色提示词和汇报契约见[协作协议](references/collaboration-protocol.md)。角色按任务独立，不要求五个子代理同时在线。根据依赖与信息价值分批派工，主控可兼任作者；依赖未到位的角色先写方法和缺口，避免互相等候。设计中的专门“对话框”可由文献子代理承担；实际创建独立用户聊天仍以用户明确的执行请求为准。

只为当前工作使用子代理；用户明确要求独立聊天时才使用创建聊天工具。若采用用户指定的现有聊天，先确认直接授权的跨聊天消息范围，记录聊天标识；对话框和 GitHub 不会自动同步研究上下文。

## 执行研究闭环

1. **冻结本轮输入。** 记录课题、轮次、数据/代码版本、源文件散列或稳定快照、待检验命题和评估判据。先完成一个低成本、最能区分竞争解释的检验。
2. **并行探索。** 猜想者优先提出少量可证伪命题；验证者独立复算并寻找最小反例；文献复查者用原文核对条件、已有结果和竞争解释；实验者执行获分配的实验；作者同步更新方法、证据位置和缺口。各自保留失败路径。
3. **到检查点汇总。** 默认每 10 分钟，以真实时间记录；短任务完成也可提前汇总。长实验返回运行标识、已完成部分和下一次检查条件，不伪造完成，也不为凑足十分钟空等。参见协议中的超时和恢复规则。
4. **质疑并裁决。** 先让验证者针对同一命题检查最强的反对证据；主控按证据修正结论，而非按多数意见决定。争议未解决就保留，记录区分解释的最小实验。
5. **同步论文、选题卡并重排任务。** 作者只接收主控已核验的证据状态，更新对应段落、图表和边界。主控记录选题各维度的变化及其原因，按间隔形成供用户决策的快照，并留下下一轮可直接执行的任务与运行清单。若还有授权预算，继续；否则交付检查点。

允许的自主研究包括本地推导、反例搜索、有限规模参数扫描、代码和数据复算、公开文献核查、获授权范围内的稿件修改。启动求解器、新增收费计算、大范围覆盖/删除、访问外部账户和发布等仍按用户授权执行；不把“自主讨论”解释为外部行动的通用许可。

## 以证据控制论文结论

维护主控单写的 `research/claims.md`：每条 C-ID 记录命题、条件/量词、证据与反证、审核者、版本、论文位置和下一个检验。采用两个相互独立的维度：

- **工作状态**：`proposed`、`testing`、`supported`、`refuted`、`unresolved`、`retired`。
- **证据类型**：`literature`、`mathematical-proof`、`analytic-derivation`、`numerical-test`、`observed-data`、`fitted-model`、`counterfactual-prediction`。

`supported` 仅表示在记录的范围内获得支持。每条证据另记 `candidate`、`reviewed` 或 `invalidated` 审核状态。只有假设和逻辑步骤完备、经独立检查的证明才能写“在这些假设下证明”；人工/agent审核不等于形式化证明器认证。模拟通过、拟合精度或多个 agent 同意均不能替代证明。没有找到反例不构成普遍正确。

有效反例必须满足原命题全部前提。收窄条件形成新版本，不把旧反例从记录抹去。输入、分析代码或前提变化时，标记相关结论及下游图表/段落待重核，保留原始证据版本。

真实论文引用需核查原文或一手文献记录，区分“书目真实”和“支持本句”。未核查引用不得补造 DOI、页码或创新性结论。写作结构、主张到章节映射见[论文蓝图](references/paper-blueprint.md)。

## ETABS 与拟合路由

当输入确实为 ETABS/CSI 数据时读取 [ETABS 研究契约](references/etabs-fitting.md)。有 `etabs-response-analysis` 时先读并复用它的流式读取、数据配对和模态参照方法；缺失时遵循本 skill 的最小契约，说明尚未覆盖的能力。

普通表格分析或成稿排版按需调用对应 spreadsheet、documents、pdf 技能，不给其他研究流程引入无关的工具依赖。仅设计框架不启动大工作簿提取或模型求解。

## 文献复查与选题决策

收到已收集论文，或猜想、证明、反例、创新性判断变化时，读取[文献复查协议](references/literature-review.md)。将可访问原文编入课题 `literature/` 或索引已有资料，按 L-ID 和页/式/图定位，与命题同一前提逐项对照。摘要或二手转述不能替代证明细节；既有论文也可能有边界或错误，冲突须交验证者独立核查。

为每个候选选题维护 T-ID，读取[选题卡协议](references/topic-cards.md)，按需采用[选题卡模板](assets/topic-card.template.md)。每个十分钟检查点复核卡片；默认每30分钟或重大变化时形成决策快照，短任务结束也交付首版。用户可指定其他间隔；未设置调度不承诺离线更新。记录问题、文献差异、候选贡献、证明/反例、数据与拟合、可行性、成稿条件和备选路线，并保留“旧判断→新判断→触发证据→下一步”的演变历史。

用户决定最终选题，团队只推荐。呈现卡片时说明本轮变化、最强支持和反对证据、可选路线及所需资源，附完整卡片位置；重大转向或需要选择时及时交付。已有用户批准的主线不能因内部讨论自动替换；用户尚未决定时继续不依赖该决定的研究。

## GitHub 与持续执行边界

Git/GitHub 用于版本和异步交接，不能替代调度器、证据账本或文件写入互斥。先检查本地是否为 Git 仓库及用户修改，远端访问和写入按本次用户授权执行；没有仓库时先以本地目录工作，不默认为用户初始化或发布。

按角色分配目录，主控单写共享状态；确需同时改同一文件时使用适当的 worktree/分支和明确整合人。小文本、脚本、运行清单适合版本化；大体积原始模型/导出数据使用本地受控路径与散列清单，上传前确认范围、大小和保密要求。不得把口令或令牌放进技能、提示词或研究日志。

默认交付可审阅本地改动，不自动 `git commit`、`git push`、合并 PR 或发布。只有获明确授权后才执行相应远端操作；PR 创建后按环境要求附回当前聊天。

若确需后台持续研究，使用当前可用的自动化工具与最新官方文档；模板见协作协议，并加入选题卡协议的定期决策版动作。一个主控定时任务读取稳定检查点，防止重入和重复实验，不为每个角色或选题卡创建互不协调的定时器。记录实际触发时间和迟到情况，不承诺精确时刻或无中断常驻。

## 验收与交付

交付能复核的研究进展：论文蓝图或稿件、主张账本、文献原文对照、选题卡及演变/待决事项、支撑脚本/数据/图表位置、反例与失败实验、未闭合问题、下一次最高信息量检验。说明实际运行了什么、结果如何及尚未验证什么。

研究完成的判断是问题得到有边界的回答且关键结果可复现；推翻原猜想或发现适用边界也可构成有价值的结果。需要新数据或用户决策时，先完成不依赖它的工作，再具体说明缺口。
